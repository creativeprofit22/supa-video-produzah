# 0003 — Graphics clips: a versioned entity on graphics tracks, with our own easing

Phase 15 stores animated graphics in the project, makes them undoable, and renders them in exports through the `supa-graphics-render` sidecar from ADR 0002.

**Entity.** A fourth track kind, `graphics`, holds `graphicsClips`. Each graphics clip carries `graphicsVersion: 1`, an `id`, a `timelineStart` and `duration` at the sequence rate, a `fontKey` from the closed caption font table, and up to 64 layers. A layer is a `rect` (width, height, corner radius, fill), `text` (≤ 500 characters, font size, fill, optional per-word or per-letter `units`) or `image` (a still-image project asset with a display size). Every layer has keyframe tracks for `x`, `y`, `scale`, `rotation` and `opacity`. A keyframe is `{ timeMicroseconds, value, easing }`, where the time is relative to the clip start and the easing is a structured object: `linear`, a named preset, `cubicBezier(x1, y1, x2, y2)`, `spring(bounce, durationMs)` or `steps(n, fromStart?)`. As in Diffusion Studio, the easing on a keyframe shapes the segment from it to the next keyframe; it is optional (linear) and ignored on the last keyframe.

**Versioning.** The project `schemaVersion` stays 2. Like speed, fades and loudness, graphics are additive optional data inside V2, so every existing V1 and V2 file parses unchanged and its stored bytes round-trip unchanged. The "migration" is per entity: `migrateGraphicsClip` (TS) and `migrate_graphics_clip` (Rust) accept `graphicsVersion: 1` and reject any other version with the typed `unsupported_schema` error. There is no older graphics format to migrate from; the version field exists so the next format change has a migration point.

**Easing math is ours.** fframes' `Easing` enum is closed and its `KeyFramesAnimation` cannot express animejs-exact springs or steps. We port `cubicBezier`, `spring(bounce, durationMs)`, `steps(n)` and the named presets from animejs 4.5.0 (via diffusion-studio-2 `lib/motion.ts`) to both TS (`packages/video-contracts/src/easing.ts`) and Rust (`graphics-renderer/src/easing.rs`). Both are checked against one fixture file, `packages/video-contracts/fixtures/easing-samples.json`: within 1e-6 of each other and within 1e-3 of animejs. The renderer samples tracks itself from the frame index and uses fframes only to turn SVG into pixels.

**Presets** (slam, pop, tiltIn, cursorDrag, rockSlide, staggered entrance, per-word and per-letter text reveal) are pure TS functions of clip duration and layer bounds that return keyframe tracks. Applying one is a single undoable `SetGraphicsClipLayers` command built by `applyMotionPreset`, so the user and, later, agents apply it in one step.

**Images** come from still-image project assets (PNG/JPEG, ≤ 4096 px per side, ≤ 32 MB, header-validated in Rust at import). The renderer receives them as bounded `data:` URIs, so the sidecar never reads files or URLs on its own.

**Export.** The render plan V2 gains optional `graphics` inputs. The TS argv puts a sentinel input `graphics:<index>` after `-i` and composites it with a time-shifted `overlay` enabled over the clip's range. Rust re-validates the plan, builds each renderer description itself from the validated data, renders it into the job's private scratch directory under the job's cancellation, and swaps the sentinel for the scratch `.mov` path at run time, as it already does for the partial output path. Export limits are lower than the project limits and are checked when the plan compiles and again when Rust validates it, before any overlay renders: at most 64 visible graphics clips per sequence, and per clip at most 16 distinct images totalling at most 40 MiB of image files (the renderer's `MAX_IMAGES` / `MAX_TOTAL_IMAGE_BYTES`). The renderer folder (executable plus FFmpeg 9 DLLs) is bundled as a Tauri resource and resolved like the FFmpeg sidecar.

**Scope.** The phase criteria stop at the stored entity, command history, easing, presets with table tests, and export: "Adding, editing and removing graphics clips go through the existing command history with undo and redo, covered by contract tests on both the TypeScript and Rust sides", "Ported motion presets … each fit to a clip duration and have table-driven tests" and "Graphics clips render through the graphics render engine in exports, verified by a scripted export test". A graphics editing UI is not part of this phase. Live preview is phase 21 ("Live preview of graphics in the editor"), and agent-authored graphics are phase 19 ("Agent graphics arrive as normal proposals that the user approves or rejects"). Until then the proposal allow-list stays closed to graphics commands, the timeline shows graphics tracks as a read-only row (`N graphics clips, non-editable`), and the preview monitor skips them.

Rejected: a schema version 3 bump, because it would force a whole-project migration and break older builds for additive data. Also rejected: storing easing as strings (`"spring(0.4, 600)"`), because structured objects validate with the same Zod/serde rules as everything else; and passing project graphics through fframes' easing, because it cannot represent springs or steps exactly.

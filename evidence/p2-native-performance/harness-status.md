# Step 3 — bounded measurement foundations (partial)

## Implemented

- `workloads.mjs`: deterministic small reference, exactly 1,000 sequential video/audio/caption items with gaps, and 1080p two-visible-layer sequence plus hidden/muted examples. Both 30/1 and 30000/1001. Constructors require two imported asset UUIDs. Sequence-level contracts pass; full disposable native projects are not yet materialized. Existing browser fixture search did not locate a reusable large decoding stress fixture. The existing timeline unit suite does contain a viewport overscan test; that is not a decoding workload.
- `generate-media.mjs`: four synthetic 40-second 1080p H.264/AAC inputs (two variants × two rates), pinned source binary identity checks, argument-array execution, no overwrite flag, unique ignored output directory, bounded process time/output, receipts with argv/hashes/probes. No microphone, system-audio capture or external media. Final receipt `runs/media-jzNbu0/receipt.json`, SHA-256 `bba8e2af2f83153304a9bd988aa8e2aad5b6d99e6dc68bdf852c5f3c777c326f`. Decoded video counts: 1,200 at 30/1; 1,199 at 30000/1001; 48 kHz audio and duration assertions passed. This proves generated input shape, not app export parity or sample-accurate audio output.
- `metrics.mjs`: bounded buffers with omission counts, nearest-rank percentiles, missing/reset counters as null, failure-preserving seek accounting, resource slope and 100 seeded seeks distributed across edge neighborhoods and timeline extent.
- `browser-observer.mjs`: opt-in video frame callbacks, quality counters when available, long tasks, DOM/visible/materialized timeline counts, capped samples and video tracking, explicit stop and lease teardown. It never writes media currentTime. Its armed seek timing currently starts **before** the UI action; values are explicitly labelled observer-arm latency, not yet exact app request-to-frame measurements. Replaced video nodes time out rather than silently following a different source. Frame callbacks are not physical presentation proof.
- `vite.profile.config.mjs`: opt-in production React profiling alias and wrappers injected only around the two named components at build time, without editing dirty application files. Unexpected component declaration shapes fail closed. Ordinary build config and CSP/assets unchanged. 20,000 commit cap, no telemetry/storage/network collection. Nested timeline commits must not be added to workspace commits as if they were separate root commits; row rerenders are not instrumented.
- `validate-profiler.mjs`: owned loopback static production preview and headless browser; real fixture initialization and split update prove both profiler callbacks fire. Finally paths close browser and preview. This is browser/mock-IPC validation, not native playback.
- `ownership.mjs`: pure refusal checks for mismatched executable/root, PID creation identity, loopback port owner and native page URL. Not a replacement for OS ancestry observations; the future driver must acquire those before CDP attachment.
- `sample-resources.ps1`: read-only five-second Windows process-tree sampling (up to 60 minutes), creation-identity matching, private/working bytes, cumulative CPU seconds, handles/process count, bounded identity tracking. Refuses non-isolated root executable. No process killing. Its rejection path is exercised; live owned-tree sampling and post-exit observation have not run.
